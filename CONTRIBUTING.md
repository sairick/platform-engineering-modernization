# Contributing to PEMM Framework

Thank you for your interest in contributing to the Platform Engineering Modernization Methodology (PEMM) Framework!

PEMM is an evolving, community-driven methodology designed to incorporate feedback, learnings, innovations, and real-world experiences from practitioners across the infrastructure modernization ecosystem.

---

## How to Contribute

### 1. Share Implementation Case Studies

Document your organization's PEMM implementation experience:

- **Organization Background** — Size, industry, infrastructure context
- **Implementation Journey** — Phases completed, timeline, challenges
- **Results Achieved** — Cost savings, employment created, technical improvements
- **Key Learnings** — What worked well, what would you do differently
- **Contact Information** — For practitioners seeking to learn from your experience

**Format:** Submit as Markdown document to the `case-studies/` directory with appropriate sector folder.

### 2. Contribute Templates and Resources

Enhance PEMM with reusable implementation resources:

- Infrastructure-as-code templates (Terraform, CloudFormation, Ansible)
- Operational runbooks and procedures
- Assessment frameworks and checklists
- Training materials and curriculum
- Decision-making frameworks

**Format:** Submit templates to appropriate directory in `templates/` with documentation explaining usage.

### 3. Improve Documentation

Help enhance PEMM documentation:

- **Clarifications** — Add examples or detail to existing documentation
- **Corrections** — Fix inaccuracies or outdated information
- **Translations** — Translate PEMM materials to other languages
- **Supplementary Guides** — Add implementation guidance based on experience

**Process:**
1. Fork the repository
2. Create a branch with descriptive name (`improve/documentation-clarity`)
3. Make changes maintaining existing structure and tone
4. Submit pull request with description of improvements

### 4. Report Issues or Suggest Improvements

Identify gaps, inaccuracies, or areas for enhancement:

- **Open an Issue** with clear description
- **Provide Context** — Explain the problem and suggested solution
- **Reference Sources** — Include supporting documentation or research
- **Propose Solutions** — Suggest how the issue could be addressed

### 5. Participate in Research & Academic Work

Support PEMM research and validation:

- Conduct and document studies on PEMM effectiveness
- Publish research on methodology outcomes
- Collaborate on academic partnerships
- Contribute to curriculum development

## Contribution Guidelines

### Content Standards

- **Accuracy:** All factual claims must be supported by credible sources
- **Clarity:** Write clearly and professionally for technical audiences
- **Completeness:** Provide sufficient detail for practitioners to understand and implement
- **Consistency:** Follow existing documentation style and structure
- **Confidentiality:** Respect organizational and individual privacy in case studies

### Documentation Requirements

**Case Studies Must Include:**
- Organization overview (industry, size, infrastructure baseline)
- Pre-implementation challenges and objectives
- PEMM implementation timeline and experience
- Measured results and outcomes
- Key learnings and recommendations
- Author/contributor contact information

**Templates Must Include:**
- Clear description of purpose and use cases
- Complete, functional content (not placeholders)
- Documentation explaining customization points
- Examples of implementation
- Testing or validation approach

**Improvements Must:**
- Maintain existing documentation structure
- Preserve validated factual content
- Clearly indicate changes made
- Reference sources for new information
- Follow professional writing standards

### Submission Process

1. **Fork the Repository**
   ```bash
   git clone https://github.com/[your-username]/platform-engineering-modernization.git
   ```

2. **Create a Feature Branch**
   ```bash
   git checkout -b feature/your-contribution-name
   ```

3. **Make Your Changes**
   - Add your case study, template, or improvement
   - Ensure consistency with existing documentation
   - Test and validate your contribution

4. **Commit with Clear Messages**
   ```bash
   git commit -m "Add case study: [Organization] [Sector] implementation"
   ```

5. **Push and Submit Pull Request**
   ```bash
   git push origin feature/your-contribution-name
   ```
   - Provide clear description of your contribution
   - Reference any related issues
   - Include contact information for follow-up

### Review Process

- **Initial Review:** Ensures contribution meets guidelines and standards
- **Technical Review:** Validates accuracy and completeness
- **Community Review:** Gathers feedback from PEMM practitioners
- **Acceptance:** Merged upon approval and meets all standards

## Community Standards

### Respectful Collaboration

- Treat all contributors with respect and professionalism
- Assume good intent in feedback and suggestions
- Provide constructive criticism focused on ideas, not individuals
- Welcome diverse perspectives and experiences

### Professional Conduct

- Maintain confidentiality of sensitive organizational information
- Respect intellectual property and attribution
- Follow professional ethical standards
- Avoid commercial solicitation or spam

### Inclusive Environment

- Welcome contributors from all backgrounds and experience levels
- Support practitioners from underrepresented communities
- Create welcoming environment for new contributors
- Foster international participation and perspectives

## Questions?

**Before Contributing:**
- Review existing documentation to avoid duplication
- Check open issues to see if topic is already being addressed
- Read recent pull requests to understand review process

**While Contributing:**
- Ask for clarification in issue or pull request comments
- Reference documentation and existing patterns
- Request feedback from maintainers if unsure about approach

**After Submission:**
- Respond to review feedback promptly
- Make requested revisions
- Engage in discussion about your contribution
